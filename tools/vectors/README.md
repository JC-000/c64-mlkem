# Test vectors — provenance

All files here are published reference data. Nothing in this directory is
generated by this project; that is the point — they are the external check on
`tools/keccak_ref.py`, which is in turn the check on the ca65 implementation.

## Tracked in git

| File | Source | What it pins |
|---|---|---|
| `KeccakF-1600-IntermediateValues.txt` | [XKCP](https://github.com/XKCP/XKCP) `tests/TestVectors/` | The 24 round constants, the 25 ρ offsets, and **240 per-step intermediate states** — 2 permutations x 24 rounds x the state after each of θ, ρ, π, χ, ι. This is the only artifact that can localise a bug to a specific round and step. |
| `SHA3_{256,512}ShortMsg.rsp` | NIST CAVP, byte-oriented | Messages 0 B up to exactly one rate block. Includes the rate-1 padding collision (suffix `0x06` and the final `0x80` bit sharing one byte → `0x86`) and the exactly-rate case that forces an extra padding block. |
| `SHAKE{128,256}ShortMsg.rsp` | NIST CAVP | Same, for the XOFs. |
| `SHAKE{128,256}VariableOut.rsp` | NIST CAVP | Varying output lengths. |
| `*Monte.rsp` | NIST CAVP | 100 chains x 1000 chained iterations per function — state transitions no single-shot vector reaches. |

CAVP archives:
`https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Algorithm-Validation-Program/documents/sha3/sha-3bytetestvectors.zip`
and `.../shakebytetestvectors.zip` (CAVS 19.0, generated 2016-01-28).

## Not tracked — fetch on demand

`*LongMsg.rsp` (~4.8 MB) are excluded by `.gitignore`. Get them with:

```sh
make vectors        # or: tools/fetch_vectors.sh
```

They add ~200 multi-block vectors (SHA3-256 up to 13,836 B). `test_keccak_ref.py`
runs them automatically when present and silently skips them when absent.

## Byte-oriented only

Only the `AllBytes` / byte-oriented CAVP sets are vendored. The bit-oriented
sets test messages whose length is not a multiple of 8, which this library's
byte-granular API cannot express and does not claim to support.

## Parsing traps

- **`Len` is in bits**, not bytes.
- **`Len = 0` still carries `Msg = 00`.** The empty-message vector has a dummy
  byte in the `Msg` field; hashing it instead of the empty string gives a wrong
  answer for the single most commonly-quoted digest in the spec. Honor `Len`.
- SHAKE Monte Carlo reports `Outputlen` as the length of the **reported**
  output, not the next chained length — an off-by-one that made the first draft
  of `test_keccak_ref.py` fail. See the comment there for the full chaining rule.
